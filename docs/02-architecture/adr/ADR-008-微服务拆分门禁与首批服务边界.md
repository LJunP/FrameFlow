# ADR-008：微服务拆分门禁与首批服务边界（定稿）

- 状态：Accepted（2026-08-12 更新定稿）
- 关联：ADR-009（数据所有权）、ADR-010（API 兼容）

## 决策

M13 只允许在模块依赖测试、业务 E2E、数据所有权和迁移/回滚方案通过后拆出：

```text
gateway-service
identity-service
project-service
asset-workflow-service
```

### 服务归属（定稿）

| 服务 | 数据 |
|---|---|
| identity-service | users、teams、team_members、refresh_token_sessions、Identity 端点的 idempotency_records |
| project-service | clients、projects、project_members、brief_versions、shot_tasks、task_comments |
| asset-workflow-service | assets、asset_versions、licenses、reviews、review_comments、delivery_packages、delivery_items |
| ai-worker | 运行日志/job store；不拥有业务表 |

- 项目计划、分镜任务、任务评论属于 project-service；
- 围绕素材版本的审核、批注、授权和交付属于 asset-workflow-service；
- AI Worker 不直接写业务表；`ai_tasks`、`suggestions` 由发起分析的业务服务拥有，Worker 通过结果事件回传；
- `identity-service` 使用 MySQL 属于工程实验轨道（M13），不是产品 MVP 架构理由；
- Delivery 暂留在 asset-workflow-service；后续如需拆分必须新增 ADR。

## 后果

- 服务数量受控，迁移可解释；
- 不共享业务数据库、不做跨库双写；
