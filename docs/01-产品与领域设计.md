# 01 · 产品与领域设计

> FrameFlow Select 唯一的产品事实源。领域概念、状态机、质检模型以本文档为准；
> 技术实现见《02-技术架构与技术栈》，开发顺序见《03-开发与学习路线》。

## 1. 产品定位

**FrameFlow Select 是一个面向 AI 生成短视频的批量质检与优选平台。**

用户向系统提交一批由同一 Prompt、Brief 或营销任务生成的候选视频（几十到几百条），
系统完成分层分析与筛选，输出：

- 明显不合格、应当淘汰的候选（附确定性证据）；
- 需要人工复核的候选；
- 批次内去重后的排名与 Top-K 优选集；
- 每个问题的规则、时间码、关键帧证据、置信度与处理建议。

**核心价值底线：减少人工完整观看量的同时，尽量避免错误淘汰真正优秀的视频。**
宁可多送几条进人工复核，也不让机器无证据地杀掉好视频。

## 2. 目标用户

- 批量生成 AI 电商短视频的个人创作者；
- AI 内容工作室、电商广告素材团队；
- 小型 MCN 与 AI 视频生成服务团队。

## 3. 非目标（明确不做）

- 不生成视频、不做浏览器内剪辑、不自动发布；
- 不预测爆款、不替代最终人工审核；
- 不做通用内容安全审核平台；
- 不做通用 Agent 平台 / Agent 基础设施；
- 不训练视频生成基础模型。

## 4. 角色模型

| 角色 | 权限 |
| --- | --- |
| OWNER | 团队与项目管理者，一切资源的最终所有者 |
| OPERATOR | 上传批次、触发分析、管理质检配置的运营者 |
| REVIEWER | 人工复核候选、调整聚类、确认优选集的审阅者 |
| VIEWER | 只读查看结果与导出的观察者 |

## 5. 端到端业务流程

```text
创建 Project
  → 写入 Prompt / Brief（不可变快照）
  → 配置 Quality Profile（可版本化）
  → 创建 Generation Batch（绑定 Profile 版本与 Brief）
  → 批量上传 Candidate 视频
  → 确定性质检（时长/分辨率/黑帧/冻结/静音…）
  → 语义质检（Prompt 对齐/质量印象/语义违反）
  → 重复聚类（精确 + 近重复）
  → 批次排名（可解释加权）
  → 人工复核 + Top-K 确认
  → 锁定 SelectionSet（不可变）→ 导出
```

## 6. 领域实体

| 实体 | 说明 | 关键规则 |
| --- | --- | --- |
| Project | 项目容器，归属团队 | 一切的根聚合 |
| Prompt / Brief | 创作提示与企业规定的不可变快照 | 创建后不可修改，只能新版本 |
| Quality Profile | 质检标准集合（阈值、启用维度、权重） | 可版本化发布；历史批次永远引用其创建时的版本 |
| Generation Batch | 一批候选视频 | 绑定 Profile 版本与 Brief；有界容量（如 20~300 条） |
| Candidate | 单条候选视频 | 记录上传会话、对象存储元数据、媒体版本 |
| Analysis Run | 一次分析执行 | 独立状态机，可重试、可取消 |
| Finding | 一条证据化的问题记录 | 见 §8 Evidence 契约 |
| SimilarityCluster | 近重复分组 | 含代表候选；聚类阈值必须版本化 |
| Ranking Snapshot | 某一时刻的固定排名 | 分数与构成固化，可复现 |
| SelectionSet | 人工确认的 Top-K 结果 | DRAFT → LOCKED；锁定后不可变、可导出 |

## 7. 状态机

**Candidate**

```text
READY → ANALYZING → ANALYZED
                  → AUTO_REJECT     （仅允许由确定性规则触发，且必须带证据）
                  → REVIEW_REQUIRED （含语义 UNKNOWN / VIOLATE 待人工判断）
                  → ANALYSIS_ERROR  （分析器故障；严禁伪装成视频不合格）
                  → INVALID         （上传即校验失败的坏文件）
```

**Analysis Run**

```text
CREATED → RUNNING → SUCCEEDED / FAILED / CANCELLED
```

**SelectionSet**

```text
DRAFT → LOCKED （锁定后内容不可变，仅可整体作废重建）
```

硬性规则：

1. `ANALYSIS_ERROR` 是系统问题，`AUTO_REJECT` 是视频问题，两者严禁混淆。
2. 语义判定只有四种：`PASS / VIOLATE / UNKNOWN / ERROR`；`UNKNOWN` 一律进人工复核，
   永不自动淘汰。
3. 所有状态迁移必须留痕（who / when / from → to）。

## 8. 质检模型

### 8.1 确定性维度（可自动淘汰）

时长、宽高比、分辨率、帧率、黑帧、画面冻结、静音、无音频轨。
由 ffprobe / OpenCV 等本地工具判定，结果可复现。
**只有确定性维度允许触发 AUTO_REJECT**，且每条拒绝必须附证据。

### 8.2 语义维度（只辅助，不自动淘汰）

- Prompt / Brief 对齐度；
- 质量印象（清晰度、稳定性、观感）；
- 语义违反（水印、乱码字幕、明显畸形等）。

由受约束的多模态模型判定，结论只能进 REVIEW_REQUIRED，由人做最终决定。

### 8.3 Evidence 契约

每条 Finding 必须携带：

- 检测器 id + 版本；
- 命中规则的语义说明；
- 时间码或帧号；
- 原始输出引用（如 probe 结果片段、关键帧图片）。

**没有证据，不允许产生任何自动结论。** AI 结果必须附带证据束；
无证据的模型结论不得自动淘汰候选。

## 9. 排名与优选

- 排名 = 确定性资格门（先淘汰）+ 可解释加权评分（维度分 × Profile 权重）；
- 聚类去重后，每个 SimilarityCluster 只推代表候选进入排名；
- Top-K 由机器推荐 + 人工复核确认，人工调整不改写机器结果，只叠加标记；
- 锁定的 SelectionSet 支持 JSON / CSV 导出。

## 10. 产品指标

| 指标 | 含义 |
| --- | --- |
| 人工观看节省率 | 1 − (人工实际观看数 / 批次候选总数) |
| 误杀率 | 被淘汰候选中经抽样人工判定为优秀的比例（越低越好） |
| 漏检率 | 最终交付后发现有明显缺陷的比例（越低越好） |
| 批次处理时长 | 从上传完成到排名产出的端到端时间 |
