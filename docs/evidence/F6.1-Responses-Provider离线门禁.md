## 1. 触发事实

所有者提供的配置界面显示：OpenCode Go、Base URL
`https://opencode.ai/zen/go/v1`、API 格式 Responses、模型 `gpt-5.6-luna`。
截图同时暴露了一枚 API Key。本轮没有转录、调用或把它写入项目与证据；但原始
聊天附件本身仍含敏感值，因此真实门禁前必须由所有者在供应商控制台撤销并生成新 Key。

[OpenCode Go 官方端点表](https://opencode.ai/docs/go/#endpoints)把
`gpt-5.6-luna` 指向 `/v1/responses`，而不是 `/v1/chat/completions`。原 Worker 仅实现
Chat Completions，因此不能把界面“能保存配置”当作 FrameFlow 已可调用。

## 2. 本地工程闭环

- Java 与 Worker 的严格目录白名单同步支持 `openai-compat`、`openai-responses`；
- `OpenAIResponsesProvider` 请求 `<baseUrl>/responses`，使用 `input_text` 与最多
  3 个 `input_image` JPEG data URL；
- 非流式响应只从 `output[].content[].output_text` 收集文本，缺失/损坏结构统一转
  Provider ERROR；
- Responses 请求不发送可选 `temperature`，避免推理模型或兼容网关拒绝显式采样
  参数；Chat Completions 旧适配器保持不变；
- OpenCode Go Luna 无密钥目录样例已固化，真实 Key 仍只由 `apiKeyEnv` 指向；
- local/dev/staging/production Compose 通过 Worker 专属 env-file 注入动态 Key；
- `check-env-isolation.sh` 要求 Provider env-file 为绝对路径、当前操作者所有、
  `0600`、非 symlink，变量名与 enabled 目录精确相等；
- `capture-provider-secrets.sh` 隐藏读取 Key，默认禁止覆盖，不把值放入命令行参数；
- Compose 展开测试证明合成 token 只进入 Worker，App/Web 均不可见。
