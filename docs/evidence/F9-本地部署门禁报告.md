## FACT：动态测试发现并修复的问题

1. 初始 App 镜像中的 JAR 没有可执行 Main-Class，容器报
   `no main manifest attribute, in /app/application.jar`。根因是模块未显式执行
   Spring Boot `repackage`；修复后重新构建并通过健康检查与 Smoke。
2. local `data` network 设置 `internal: true` 时，Docker Desktop 无法为 MinIO
   安装宿主 loopback 端口转发，浏览器上传链不可达。local 保持普通隔离 bridge；
   dev/staging/production 则保留 internal `data`，只把 MinIO 额外接入不承载
   DB/Redis/MQ 的 `media` bridge。用等价远程拓扑动态探针验证宿主 loopback MinIO
   health 与浏览器 CORS 均 `PASS`，没有把整个数据网暴露出去。
3. RabbitMQ 3.13 已脱离支持基线；Compose、测试与故障工具迁移到 digest-pinned
   4.3.5，并用实际产品链和 MQ 120 条演练验证兼容性。
4. Compose file secret 不会替宿主 JWT key 重映射 UID。生成器现在只允许 root
   `--apply`，安装为 `10001:10001`、私钥 `0400`、公钥 `0444`；App 镜像以真实
   `10001:10001` 身份 bind mount 读取私钥的动态探针为 `PASS`。
5. 晋级/回滚不再信任既存 `release.env`：每次先从已验证 manifest 原子生成期望
   projection 并逐字节比较，篡改负例在任何 Docker 操作前 fail-closed。
6. Smoke 不再只看 Worker 容器为 Running，而是读取实际
   `frameflow_worker_ready{...}=1`；告警也同时覆盖 scrape down、readiness=0 和
   readiness 缺失。修正带 environment label 的解析后，全栈 Smoke 再次 `PASS`。
7. Handoff byte-tamper 负例首次发现 Bash 在 `if`/`||` 调用函数时不会让内部
   `set -e` 可靠中止，失败的 checksum 返回码可能被后续成功的 file-set diff 覆盖。
   安装器现对摘要失败显式 `exit 1`；同一篡改负例复验已 fail-closed。
