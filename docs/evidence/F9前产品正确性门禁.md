## 6. F6.1 平台多模型选择增量证据

本轮在不接触真实 Provider 的边界内新增并验证：

- Java 启动期严格解析平台目录；非法字段、直接 Key、未知 Provider、非法 URL、
  未启用默认项均 fail-closed；`GET /api/v1/semantic-models` 需 JWT，响应精确
  排除 `baseUrl`、`apiKeyEnv`、Key 和私有地址；
- 新 Profile 只能选择 enabled `modelId`；省略时把当时默认 ID 写入不可变 JSONB
  版本；模拟旧版本缺少 `modelId` 时读取不改写；
- Worker 按逻辑 ID 选中各目录项的实际模型名、端点和专属 Key 环境变量。离线 stub
  捕获证明选中了正确路由；未知/停用/目录损坏/缺 Key 均逐维度 `ERROR`，没有
  default、legacy 或 Fake 的静默回退；
- 成功与错误 Evidence 只记录逻辑 `modelId` 和实际 `model`，测试确认不包含
  Key、Key 环境变量名或 `baseUrl`；
- Web 只展示 enabled 项，目录加载失败、空目录或失效选择会禁止提交已启用 AI
  的 Profile；AI 关闭时不受目录故障影响；生产构建与 14 条契约测试通过；
- 提供无密钥双模型样例
  `experiments/fixtures/pre-f9-correctness/model-catalog.example.json` 与
  《F6.1 源码导读》，供所有者后续统一测试。

这证明目录、选择、路由和脱敏的工程契约，不证明任何真实模型端点可达或模型
质量。此次未进行真实 Provider 网络调用，也没有对新增选择器另做一次浏览器人工回归；
后者按所有者安排留到统一测试。
