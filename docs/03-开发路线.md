# 03 · 开发路线（功能驱动）

> FrameFlow Select 是产品工程，不是课程作业。目标是把质检与优选平台做出来、
> 测绿、能部署。产品语义见《01》，技术选型见《02》。

## 0. 协作与推进

### 0.1 分工

- **开发**：实现功能的代码、测试与部署配置；需要时更新 `docs/guides/` 下的模块说明。
- **产品决策**：方向、验收、发布审批由项目负责人拍板。
- **线上操作**：购买服务器、SSH、DNS、生产发布由有权限的人亲手执行；仓库内准备配置、脚本和操作说明。

### 0.2 注释

核心逻辑（状态机、事务、幂等、权限、并发、关键算法）用简短注释写清为什么这样设计、改坏会怎样。不复述代码字面意思，不给样板代码刷注释。

### 0.3 功能交付

代码与测试全绿：`./mvnw -B verify`，以及对应的 Worker / Web 校验。新增或修改 API 必须同步 `docs/api/frameflow-v1.yaml`。

### 0.4 推进纪律

1. Git：`main` 是唯一长期主线；隔离开发用临时 `codex/<短名>` 分支，合回后删除。conventional commits（feat/fix/test/docs/chore）。
2. 不 force push、不改写已推送历史、不删除 `.git`。
3. 不通过改测试/阈值/已执行迁移制造 PASS。
4. `ANALYSIS_ERROR` 严禁伪装成视频不合格。
5. 生产是否可用、试点是否证明价值，只能依据真实运行数据判断，不能用本地合成结果代替。

## F1 · 工程基线与用户认证

**目标**：建立工程基线；产品能注册、登录、携带 JWT 访问受保护接口。

**关键技术**：Git 分支/合并/回滚流程；Maven 多模块与生命周期；
Spring Boot 启动与自动配置；REST 接口与 Bean Validation；Spring Security +
JWT（RS256 签发/刷新/过期）；Flyway 首批迁移（用户/团队/成员表）；
PostgreSQL 接入；JUnit 单测 + @SpringBootTest 集成测试 + Testcontainers。

**任务分解**：
- T1 `GET /api/v1/ping`（返回版本与时间）+ 自定义配置读取 + 单测/集成测试，
  走完整 feature 分支流程；
- T2 用户/团队/成员表设计与 Flyway 迁移；
- T3 注册/登录/刷新 Token 接口（密码哈希、RS256、短时效）；
- T4 受保护资源示例接口 + 401/403 越权负例测试；
- T5 请求幂等记录表与中间件。

**完成标准**：ping 与认证接口 curl 可用；错误返回统一错误模型；
verify 全绿含越权负例；能讲清 Spring Boot 启动流程与 JWT 链路。


## F2 · 项目与质检配置管理

**目标**：实现 Project、Prompt/Brief（不可变快照）、Quality Profile（版本化）的
完整 CRUD 与权限控制。

**关键技术**：领域建模（聚合/不变量）；PostgreSQL 索引、事务隔离、约束、
乐观锁；MyBatis SQL 编写与分页；OpenAPI 契约先行 + 契约差异测试；
ArchUnit 模块边界守护。

**任务分解**：
- T1 Project CRUD + 角色权限（OWNER/OPERATOR/REVIEWER/VIEWER）；
- T2 Brief 不可变快照（创建后只读，修正=新快照）；
- T3 Quality Profile 版本化（发布新版本，历史批次引用旧版本）；
- T4 OpenAPI 契约与运行时一致性测试 + ArchUnit。

**完成标准**：三个资源 CRUD 全绿；权限矩阵负例齐；Profile 版本引用规则有测试
证明。


## F3 · 批次与视频上传

**目标**：创建 Generation Batch，批量上传候选视频，字节进 MinIO、元数据进 PG。

**关键技术**：MinIO/S3 API；Presigned URL 直传；Multipart 分片上传与断点；
对象版本与生命周期；媒体元数据（ffprobe 的 duration/分辨率/帧率）；
上传会话状态机与部分失败对账。

**任务分解**：
- T1 Batch 创建（绑定 Profile 版本 + Brief，有界容量校验）；
- T2 Presigned URL 申请 + 客户端/脚本直传 + 完成确认回调；
- T3 Candidate 元数据入库（bucket/key/校验和/媒体探针结果）；
- T4 上传部分失败对账与重传；
- T5 可复现的合成测试视频生成脚本。

**完成标准**：单文件与分片上传均可回放验证；坏文件进 INVALID 且证据留痕；
MinIO 故障后元数据对账脚本可用。


## F4 · 确定性质检流水线

**目标**：批次触发分析 → RabbitMQ 派发 → Python worker 执行确定性检测 →
结果幂等回写，产出带证据的 Finding。

**关键技术**：RabbitMQ（ACK、Publisher Confirm、重试上限、DLQ、死信重放）；
批次调度与背压；Python 工程化（打包、配置、日志、pytest）；ffprobe/OpenCV
检测器（黑帧/冻结/静音/时长/分辨率/帧率）；幂等回写；ANALYSIS_ERROR 语义。

**任务分解**：
- T1 Analysis Run 状态机 + 批次调度（并发与上限）；
- T2 RabbitMQ 派发与消费骨架（Confirm/ACK/重试/DLQ）；
- T3 Python worker：任务拉取 + ffprobe 元数据核验检测器；
- T4 黑帧/冻结/静音检测器（OpenCV）+ pytest 用例；
- T5 结果幂等回写接口（重复回放不产生重复 Finding）；
- T6 DLQ 重放工具与积压告警。

**完成标准**：上传→分析→Finding 全链路 E2E 测试通过；杀掉 worker 中途恢复
不丢任务不重复结论；坏视频进 ANALYSIS_ERROR 而非 AUTO_REJECT；DLQ 可重放。


## F5 · 缓存与限流（Redis）

**目标**：给热点路径加缓存与限流：登录限流、批次进度缓存、项目列表缓存。

**关键技术**：Redis 数据结构与 TTL；Cache-Aside 与一致性；缓存穿透/击穿/雪崩
防护；限流算法（固定窗口/令牌桶）；宕机降级（Redis 挂了业务仍可用）。

**任务分解**：
- T1 登录接口限流（令牌桶）；
- T2 批次进度查询缓存（Cache-Aside + 短 TTL + 失效广播）；
- T3 穿透/击穿防护（空值缓存/互斥重建）；
- T4 Redis 宕机降级演练（记录降级路径与恢复）。

**完成标准**：限流与缓存各有正反测试；演练有记录；能解释每种缓存策略的
失效场景。


## F6 · 语义质检（AI Provider）

**目标**：接入多模态模型做 Prompt 对齐/质量印象/语义违反检测，结论只进
人工复核，每条带证据束。

**关键技术**：Provider Adapter 模式（可替换/Mock/故障可观测）；
prompt 快照与版本化；预算/超时/限流边界；批量调用的并发控制；
离线评测集与指标（准确率/误杀率）；证据束（时间码+帧+原始输出引用）；
平台托管模型目录、密钥隔离与不可变 Profile 模型选择。

**任务分解**：
- T1 语义 Provider SPI + Fake Provider（可测）；
- T2 OpenAI 兼容适配器（无 Key 形成语义 ERROR，不静默 Fake）；
- T3 语义 Finding + 证据束落库（UNKNOWN→REVIEW_REQUIRED）；
- T4 离线评测集：标注样本 + 评测脚本 + 指标报告；
- T5 批量调用预算控制与降级。
- T6 平台多模型目录 + 安全目录 API + Profile 版本化选择 + Worker 白名单路由。
- T7 Chat Completions / Responses 双协议多模态适配与 Worker-only Secret 注入。
- T8 单请求真实门禁：合成视觉挑战、无重试预算、脱敏 Evidence 与源码提交绑定。
- T9 完整产品真实门禁：单候选合成 MP4 经 API→MinIO→RabbitMQ→Worker→Provider
  →Java 回写→排名→锁定→导出；进程预算与禁重启共同保证最多一次外部请求。

**完成标准**：Fake Provider 全链路测试；至少两个平台模型的目录/选择/路由
契约自动化通过，浏览器看不到端点与密钥；真实 Provider 有一次真实调用记录；
评测报告能复现；语义结论无一触发自动淘汰。

**当前验证事实（2026-08-25）**：2026-08-24 的 OpenCode Go `gpt-5.6-luna`
Responses Adapter 单请求门禁为 PASS。2026-08-25 首次完整尝试因旧合成视频被本地
冻结检测判为 BLOCKER 而 fail-closed；修复后的独立授权重试在请求前以同一检测器
确认黑帧/冻结均为 0，并以恰好 1 次 `/responses` 请求跑通 API→MinIO→MQ→Worker
→Luna→Java 回写→排名→锁定→JSON/CSV。三项语义 PASS、候选 `ANALYZED`、Selection
`LOCKED`，39 项检查全部 PASS。该记录关闭本地完整真实 Provider 合成产品链门禁，
但不等于生产发布、真实客户试点或价值证明。

为什么同一个逻辑模型 ID 不能原地换绑另一个实际模型？

## F7 · 重复聚类、排名与 Top-K 优选

**目标**：精确/近重复聚类，可解释加权排名，人工确认 Top-K，锁定导出。

**关键技术**：感知哈希/相似度计算；近重复聚类（阈值版本化、稳定代表选择）；
加权评分模型（权重来自 Profile）；Ranking Snapshot 固化；SelectionSet
DRAFT→LOCKED 不可变；JSON/CSV 导出。

**任务分解**：
- T1 精确重复检测（校验和）；
- T2 近重复（感知哈希 + 阈值聚类 + 代表候选规则）；
- T3 资格门 + 加权排名 + Snapshot 固化；
- T4 人工复核接口（调整只叠加标记不改机器结果）；
- T5 SelectionSet 锁定 + JSON/CSV 导出。

**完成标准**：合成重复集聚类正确；排名可复现（同输入同输出）；
锁定后不可变有测试；导出文件字段完整。


## F8 · Web 前端产品化

**目标**：Next.js 轻前端覆盖核心闭环：登录 → 项目/批次列表 → 上传 →
进度 → 候选审阅（视频播放 + Finding 时间线）→ 优选 → 导出。

**关键技术**：App Router、数据获取与缓存、JWT 存储与刷新（HttpOnly 优先）、
直传分片上传、视频播放器与时间码联动、类型安全（TS 与 OpenAPI 生成）。

**任务分解**：
- T1 登录态与请求层（token 刷新、401 处理）；
- T2 项目/批次列表与创建；
- T3 上传页（Presigned 直传 + 进度）；
- T4 候选审阅页（播放器 + Finding 时间线 + 语义结论展示）；
- T5 优选/对比/导出页与整体视觉打磨；
- T6 移动端可用性检查。

**完成标准**：桌面浏览器全闭环可用；token 不落在 localStorage 明文；
构建与类型检查零错误。


## F9 · 服务器部署与 CI/CD

**目标**：产品部署到自有 Linux 服务器：dev/staging/production 三级环境，
GitHub Actions 全自动构建晋级。
**注**：购买服务器、SSH、DNS、发布审批由有权限的人亲手执行；仓库内准备配置、脚本与操作说明。

**关键技术**：Linux 基础（SSH 加固、非 root 用户、防火墙、journalctl）；
Docker/Compose 编排全套服务；Nginx 反代 + HTTPS 证书自动续期 + 502 排查；
域名与 DNS；GitHub Actions 流水线；镜像构建/推 Registry/环境晋级
（build once, promote same image）；Smoke Test 与回滚。

**任务分解**：
- T1 非 prod VPS 初始化与安全加固（配置与脚本入库，操作在目标机器上执行）；
- T2 Docker Compose 部署 PG/Redis/RabbitMQ/MinIO/应用；
- T3 Nginx + HTTPS + 域名，dev 与 staging 逻辑隔离；
- T4 Actions：PR→测试→构建镜像→dev 部署→Smoke；
- T5 staging 手动晋级 + 回滚演练；
- T6 production VPS 独立部署 + 人工审批发布。

**完成标准**：三环境域名可访问且数据完全隔离；一键回滚演练成功；
发布日志可追溯（SHA+版本+Digest）。


## F10 · 生产化运维

**目标**：production 有监控、告警、日志、备份与故障演练。

**关键技术**：Prometheus + Grafana 指标与告警；结构化日志与 Loki；
数据库备份与恢复演练；MinIO 数据保护；故障演练（Redis 宕机/MQ 积压/
worker 崩溃/DB 不可连接/磁盘不足/错误版本发布）与事故复盘。

**任务分解**：
- T1 指标暴露 + Grafana 面板 + 告警通道；
- T2 日志聚合与检索；
- T3 定时备份 + **真实恢复演练**（恢复到另一实例验证）；
- T4 三个以上故障演练 + 复盘文档。

**完成标准**：核心指标可视化且告警可触达；恢复演练有证据；
每个演练有时间线复盘。


## F11 · 真实试点验证

**目标**：用真实视频、真实模型、真实人工审核验证产品价值。

**关键技术**：试点设计（指标口径）；真实数据合规与脱敏；
人工审核协议；指标统计与结论诚实性。

**任务分解**：
- T1 试点方案：批次来源、审核人、指标口径；
- T2 真实批次跑通全流程并人工复核；
- T3 指标报告：人工观看节省率、误杀率、漏检率；
- T4 结论：`PILOT_VALUE_PROVEN` 或 `PILOT_NOT_PROVEN`
  （只依据数据，不依据愿望）。

**完成标准**：至少一个真实批次完整走完；报告数据可复现；
结论措辞与证据一致。
