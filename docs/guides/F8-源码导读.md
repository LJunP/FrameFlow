# F8 源码导读 · 视频质检工作台

> F8 把 F1–F7 的后端能力接入一个可操作的 Next.js 工作台。本文只描述当前仓库实际存在的源码；F12 新增的品牌首页、账户与团队体验见《F12 源码导读》。

## 1. 阅读地图

| 顺序 | 文件 | 一句话说明 |
|---|---|---|
| 1 | `lib/auth-context.tsx` | access token 仅存内存，refresh token 由 HttpOnly Cookie 承载，会话恢复区分未登录与临时故障 |
| 2 | `app/api/auth/[action]/route.ts` | 登录、注册、刷新与登出的专用 BFF；响应体不向浏览器暴露 refresh token |
| 3 | `app/api/gw/[...path]/route.ts` | 受限业务 API 网关；拒绝认证路径与路径逃逸 |
| 4 | `lib/api.ts` | 稳定 API 引用、401 单飞刷新、GET 瞬断重试与 XHR 上传进度 |
| 5 | `app/workspace/page.tsx` | 登录后的项目列表与项目创建入口 |
| 6 | `app/projects/[id]/page.tsx` + `lib/quality-profile.ts` | Brief 快照、业务化质量规则与批次创建 |
| 7 | `app/batches/[id]/page.tsx` | 批次动作、单文件 SIMPLE 直传、候选列表与 3 秒状态轮询 |
| 8 | `app/candidates/[id]/page.tsx` | 视频播放、确定性/语义 Finding 双区时间线与时间码跳转 |
| 9 | `app/selections/[id]/page.tsx` | 排名信息、机器/人工动作双列、锁定与 CSV/JSON 导出 |

## 2. 核心 ★ 索引

| 核心 | 位置 | 解决什么问题 |
|---|---|---|
| token 分层 | auth context + auth route | access 不落 localStorage；refresh 不进入页面 JavaScript |
| 单飞刷新 | `api.ts refreshSession()` | StrictMode 或并发 401 时只轮换一次 refresh token |
| 稳定请求对象 | `useApi()` | token 变化不重建页面依赖的 API 对象，避免 effect 重发与请求循环 |
| 认证网关隔离 | 两个 route handler | `/api/gw/auth/*` 被拒绝，认证只能走会剥离 refresh token 的专用 BFF |
| XHR 直传 | `putWithProgress()` | 浏览器直接 PUT 到对象存储并显示原生进度 |
| 语义安全边界 | 候选页 + ingestion | 语义结论只供人工复核；`ANALYSIS_ERROR` 在 UI 明确标为系统异常 |
| 机器/人工双列 | selection page | `machinePick` 与 `humanAction` 分开显示，不改写机器事实 |
| blob 下载 | selection page | 导出请求需要 Bearer，不能用普通 `<a href>` 代替 |
| 质量规则转换 | `quality-profile.ts` | 用户编辑业务字段，只在请求边界生成后端既有 `spec` JSON 字符串 |

## 3. 当前真实请求流

```text
登录   POST /api/auth/login
        → Java /api/v1/auth/login
        → refreshToken 写入 HttpOnly Cookie
        → accessToken、user、team 返回 AuthContext

上传   POST /api/gw/batches/{id}/candidates
        → 当前 Web 只处理带 uploadUrl 的 SIMPLE 指令
        → XHR PUT 对象存储 → POST /candidates/{id}/complete

分析   POST /batches/{id}/analyze
        → 批次页在存在 PENDING_UPLOAD / ANALYZING 时每 3 秒重载批次、候选和优选集

审阅   GET /candidates/{id}/content-url（URL + 候选状态）+ /findings
        → ANALYSIS_ERROR 由服务端状态驱动系统异常提示，不能从“Finding 为空”猜测
        → 点击 Finding 时设置 video.currentTime
        → 证据由用户展开 `<details>` 查看

交付   GET selection → GET ranking/latest → GET candidates
        → POST selection items（当前 UI 只提交 INCLUDE / EXCLUDE）
        → POST lock → fetch export → blob 下载
```

## 4. 当前源码边界

以下能力在后端或历史设想中存在，但当前 Web 源码没有实现，不能在导读中写成已交付 UI：

- 断点续传、失败自动重试与 `/reconcile` 对账界面（多文件选择、拖放排队与 Multipart 分片上传已在批次页交付）；
- SIMPLE 上传完成只代表对象已登记；关闭批次并点击“触发分析”后才会真正派发 MQ；
- 批次主数据与增强数据的 `Promise.allSettled` 独立降级；当前 `load()` 是顺序请求；
- 候选三栏布局、Finding Tab、selected Finding 与证据自动同步；
- 优选备注编辑、锁定时间展示和自定义锁定确认面板；当前使用浏览器原生 `confirm()`；
- `components/ui/primitives.tsx`、`components/domain/quality-profile-editor.tsx` 以及 `form-stack`、`panel-footer`、`candidate-table`、`selection-table`、`table-wrap`；这些路径或类名不存在。

当前质量规则编辑器直接位于项目页。它支持时长、最小分辨率、最低帧率、AI 复核维度和近重复阈值；权重采用代码中的默认值，没有面向用户的权重编辑器。

## 2026-09-13 批次界面修复

`app/batches/[id]/page.tsx` 以每页 50 条读取候选并显示服务端总数；翻页使用请求序号
