> 后端 91 个测试保着的 API，终于有了能看的脸。本导读的关键不在页面，

## 1. 阅读地图

| 顺序 | 文件 | 一句话说明 |
|---|---|---|
| 1 | `lib/auth-context.tsx` | 内存 access + cookie refresh 的会话状态 |
| 2 | `app/api/auth/[action]/route.ts` | **token 安全的服务端半边**：HttpOnly cookie 的流转 |
| 3 | `app/api/gw/[...path]/route.ts` | 同源代理：零 CORS + 隐藏后端拓扑 |
| 4 | `lib/api.ts` | 请求层：401 单飞刷新重试 + XHR 直传进度 |
| 5 | `app/login/page.tsx` → `app/page.tsx` → `app/projects/[id]` | 登录 → 项目 → Brief/Profile/批次 |
| 6 | `app/batches/[id]/page.tsx` | 批次指挥台：上传/关闭/分析/排名/优选 + 3s 轮询 |
| 7 | `app/candidates/[id]/page.tsx` | 审阅页：播放器 + 双区 Finding 时间线（点击跳转画面） |
| 8 | `app/selections/[id]/page.tsx` | 优选集：机器/人工双列展示、锁定、导出 |

## 2. 核心 ★ 索引

| 核心 | 位置 | 解决什么问题 |
|---|---|---|
| token 三层存放 | auth-context + route.ts | access 在内存（刷新即失→静默续期）；refresh 在 HttpOnly cookie（JS 不可读）；localStorage 永不放 token |
| 单飞刷新 | api.ts refreshSession | StrictMode 双挂载下防轮换竞态（E2E 实测抓到） |
| 同源代理 | gw route | 免 CORS 配置；API_BASE 是服务端 env，浏览器不见后端 |
| XHR 直传 | putWithProgress | fetch 没有上传进度事件；浏览器 PUT presigned URL 直达 MinIO |
| blob 下载 | selections page | `<a>` 带不上 Authorization——导出必须 fetch+blob |
| 双列并存展示 | selections 表格 | machine_pick 与 human_action 各一列——审计语义在前端也不丢 |
| 短时效播放地址 | content-url 接口 | 每次进审阅页现签 15 分钟，不长期公开对象 |

## 3. 一次"点击查看"背后的请求流

```text
登录   POST /api/auth/login（同源 Next 路由）
        → Java /auth/login → refreshToken 写入 HttpOnly cookie
        → accessToken 返回 → 只存 React 内存
数据   GET /api/gw/projects（同源代理附加 Bearer 内存 token）
        → 401? → POST /api/auth/refresh（单飞，cookie 换新对）→ 重试一次
上传   POST /api/gw/batches/1/candidates → 拿 presigned URL
        → XHR PUT 直达 MinIO（带进度条）→ POST complete
看片   GET /api/gw/candidates/1/content-url → 15 分钟 GET URL → <video src>
```

## 4. E2E 实测抓到并修掉的 5 个真 bug

1. **waitForConfirms(5)**：参数是毫秒不是秒，本地慢 broker 上分析派发
   必超时（测试里 broker 快从未暴露）。
2. **StrictMode 双挂载刷新竞态**：并发两次静默刷新 → 第二次用已被
   轮换吊销的旧 token → 401 → cookie 被清 → 登录态意外丢失。
   修复：single-flight（并发共享同一 Promise）。
3. **导出用 `<a>` 链接**：浏览器导航带不上 Authorization → 401。
   修复：fetch + blob 下载。
4. **location.href 跳转**：整页重载丢内存 token 且中断在途请求。
   修复：router.push（SPA 导航）。
5. **缺 Profile 创建 UI**：页面盘点时发现的功能缺口。

另有已知 dev 噪音：Next dev 模式下轮询偶发 "Failed to fetch"
（代理请求撞上 HMR/重启窗口），下一轮轮询自愈；生产构建无此现象。

## 5. 本地跑起来（三终端）

```bash
docker compose -f infra/local/docker-compose.yml up -d
# 终端 1
./mvnw spring-boot:run -pl frameflow-app
# 终端 2
cd frameflow-web && npm run dev
# 浏览器 http://localhost:3000 —— 注册→项目→Brief→Profile→批次→上传→
#   关闭→分析→排名→优选集→人工调整→锁定→导出
```
