## 3. 关键技术点讲解

### 3.1 一次带认证的请求走过了什么

```text
HTTP GET /api/v1/me (Authorization: Bearer xxx)
 → Tomcat → Spring Security 过滤器链
    → BearerTokenAuthenticationFilter：取 token → NimbusJwtDecoder 验签+验 exp
    → JwtAuthenticationConverter：role claim → ROLE_OWNER 权限
    → authorizeHttpRequests 规则：anyRequest().authenticated() ✓
 → DispatcherServlet → MeController.me(@AuthenticationPrincipal Jwt)
 → AuthService → MyBatis SQL → PostgreSQL → JSON 响应
```

任何一步失败：验签失败/无 token → 401（JSON，两个入口都接了统一出口）；
角色不够 → 403。**Controller 之前的失败 @RestControllerAdvice 接不到**，
这就是 SecurityConfig 里必须手写 entryPoint 的原因。

### 3.2 双令牌模型（本功能最重要的设计）

```text
access token  = JWT, 15 分钟, 无状态(不查库), 不可吊销
refresh token = 随机串, 14 天, 有状态(库里存哈希), 可吊销/一次性

登录 → 发一对；access 过期 → 用 refresh 换新对（旧的 refresh 立即作废）
登出 → 吊销全部 refresh；手里的 access 最多再活 15 分钟
```

为什么这样切：JWT 的优势是不查库、劣势是收不回；不透明 token 正相反。
让长命的那个可吊销、短命的那个自然死亡，两头都占到。

### 3.3 三层越权防线（对应三个测试）

| 防线 | 场景 | 返回 | 测试 |
|---|---|---|---|
| 认证 | 无 token / 坏 token | 401 UNAUTHENTICATED | me_without_or_with_invalid_token |
| 防枚举 | 查别人的团队 | 404 RESOURCE_NOT_FOUND | foreign_team_returns_404 |
| 授权 | 团队内非 OWNER | 403 FORBIDDEN | non_owner_member_gets_403 |

### 3.4 幂等：为什么"先查后插"是错的

两个同 key 请求并发到达 → 都查到"没有记录" → 都执行业务 → 双落库。
正确姿势是 `INSERT ... ON CONFLICT DO NOTHING` 让数据库用主键保证
只有一个赢。应用层判断 + 数据库兜底，与"邮箱查重 + UNIQUE"同一思想。

### 3.5 本次开发中真实踩过的坑（比代码更值钱）

1. **`-parameters`**：接口 500，堆栈 `Name for argument not specified`。
   原因：没继承 spring-boot-starter-parent 就没有默认的编译参数，Spring 6.1+
   解析不了 @PathVariable 参数名。已固化在根 pom。
2. **Docker API 版本**：Testcontainers 报"找不到 Docker 环境"，但 curl 正常。
   定位方法：逐版本 curl `/v1.xx/info`——Docker 29 的 minAPI=1.40，旧版全部
   400 空壳。解法：surefire 注入 `api.version=1.44`。
3. **无效 token 的 401 是空体**：Bearer 过滤器不走全局 entryPoint，
   必须在 oauth2ResourceServer 上单独接。
4. **测试断言整串 JSON 相等**：timestamp 毫秒不同导致误报——防枚举测试
   应比较 code+message。
5. **兜底异常必须打日志**：没日志的 500 只能瞎猜（本次靠加日志才看到坑 1）。

## 4. 本地运行与亲眼验证

```bash
# 1. 起数据库（首次会拉镜像）
docker compose -f infra/local/docker-compose.yml up -d

# 2. 起应用
./mvnw spring-boot:run -pl frameflow-app

# 3. 另开终端验证
curl http://127.0.0.1:18080/api/v1/ping

# 注册（注意必须带 Idempotency-Key）
curl -X POST http://127.0.0.1:18080/api/v1/auth/register \
  -H "Content-Type: application/json" -H "Idempotency-Key: try-1" \
  -d '{"email":"me@example.com","password":"Passw0rd!","displayName":"我"}'
# → 拿到 accessToken；同一 key 再发一次，对比两次响应是否一字不差

# 不带 token 访问受保护接口 → 401 JSON
curl -i http://127.0.0.1:18080/api/v1/me

# 带 token 访问 → 200
curl -H "Authorization: Bearer <accessToken>" http://127.0.0.1:18080/api/v1/me

# 全量测试（会自动用 Docker 起真实 PostgreSQL）
./mvnw clean verify
```
