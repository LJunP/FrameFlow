# F12 源码导读 · 品牌前台、账户与团队入口

> F12 是在 F8 工作台之上补齐的产品体验切片：公开品牌首页、认证入口、工作台导航、个人中心和当前团队只读页。
> 本切片的边界是“真实可用而不伪造能力”：没有后端支持的资料编辑、邀请成员、多团队切换和后台管理不会被 UI 假装出来。

## 2. 路由和壳层边界

`AppShell` 先读取 pathname，再根据 `ready && user && workspacePath(pathname)` 判断是否进入工作台壳层：

- `/` 是公开品牌首页，始终不加载项目、批次或团队业务数据；
- `/login` 是独立认证壳层，不把登录表单包进侧栏；
- `/workspace`、`/projects/*`、`/batches/*`、`/candidates/*`、`/selections/*`、`/team`、`/account` 由工作台壳层承载；
- 未登录进入受保护页面时，由 `AppShell` 在 `ready` 且没有 `sessionError` 后统一跳转 `/login?next=...`，避免 refresh 恢复期间提前误判；
- 临时网络或认证上游故障不会被当成“已退出”，受保护页面显示重新验证入口；
- 工作台品牌 Logo 回到公开 `/`；项目、批次、候选和优选加载失败均提供 `/workspace` 回退。

## 3. 认证跳转安全

`safeNext()` 使用固定可信 origin 解析目标，并只接受工作台已知路由。`//evil.example`、`/\evil.example`、绝对 URL、脚本协议和非工作台路径都回退到 `/workspace`。登录页的模式切换只通过 URL 查询参数表达状态，方便分享 `/login?mode=register`，同时保留受控的 `next`。

登录成功后调用真实 `/api/auth/login`，注册成功后调用真实 `/api/auth/register`；响应中的 access token 交给 `AuthContext` 存在 React 内存，refresh token 由 Next 同源认证路由写入 HttpOnly Cookie。不要为了“记住登录”把 token 写入 localStorage。

通用 `/api/gw/*` 明确拒绝 `auth` 前缀和非法路径段，避免绕过专用 BFF 读取 refresh token，或用双编码路径逃出 `/api/v1/`。401 续期会同步 `accessToken + user + team`；角色变化后 UI 不继续沿用旧 principal。登出先清内存，再调用有界 BFF；无论上游吊销成功、超时还是不可达，BFF 都及时清除 HttpOnly Cookie。

## 4. 营销层和工作台主题隔离

营销页采用自制 HTML/CSS 示意图表达帧序列、Finding、评分和时间轴，没有第三方影视素材、客户数量或虚构案例。`globals.css` 中 `--ff-*` 主要定义品牌色与营销视觉，工作台复用其中少量品牌强调色，但仍以 `--bg`、`--surface`、`--line` 等高对比令牌承载表格和状态。

动效以短时长的位移、透明度和颜色/边框过渡为主：首屏装饰漂浮、产品示意卡片入场、导航和卡片 hover。没有滚动劫持、自动播放声音、Canvas 或 WebGL。`prefers-reduced-motion: reduce` 会停用持续漂浮和入场动画，并取消关键过渡，让静态内容直接可读。移动工作台侧栏在关闭时不可见且不进入 Tab 顺序；打开后首项获焦，Escape 和菜单导航都会把焦点带回可见控件。

## 5. 业务化质量规则编辑器

项目配置页不再要求普通用户直接输入 `spec JSON`。`lib/quality-profile.ts` 用 `QualityProfileDraft` 保存可读字段：时长、最小分辨率、帧率、AI 复核维度和近重复灵敏度。提交前由 `validateQualityProfileDraft()` 检查范围和逻辑关系，例如最长时长不能小于最短时长、启用 AI 时至少选择一个维度；通过后才由 `serializeQualityProfileDraft()` 生成后端既有 `spec` 字符串。

这层转换保持了后端 F2/F4/F6/F7 契约的稳定性，同时把 Worker 内部字段隔离在 API 边界。AI 选项明确标记为“提示，不自动淘汰”；`VIOLATE`、`UNKNOWN` 和 `ERROR` 仍按项目红线进入人工复核。

## 6. 账户与团队页的真实能力边界

`/account` 只显示 AuthContext 已经拥有的昵称、邮箱、当前团队和角色，并提供真实登出操作。资料编辑、密码修改、活跃设备和订阅信息没有 API 支撑，因此只用说明文字标记为后续能力，不放假保存按钮。

`/team` 只在当前角色是 `OWNER` 时调用 `GET /teams/{teamId}/members`。非 Owner 不发送 Owner-only 请求，而显示权限说明。成员邀请、角色调整、移除成员、所有权转移和多团队切换需要后端迁移、审计和重新签发团队 JWT，不能只改前端状态。
