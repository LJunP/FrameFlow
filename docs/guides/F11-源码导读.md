## 2. 一键调用链

```text
run-synthetic-rehearsal.sh
  → 解析并 sentinel 校验仓库根
  → generate_dataset()
      → 本机 FFmpeg，或固定 Digest 的本地 Docker 镜像
      → --pull=never + --network=none + --rm
      → 10 条媒体 + 4 张 PNG + 10 条标注 + 300 条压力记录
  → validate_package()
      → 执行 manifest/annotation Schema
      → 校验相对路径、symlink、bytes、SHA-256、ffprobe 与盲评隔离
  → calculate_metrics()
      → 时长加权主指标 + 条数辅助指标 + 误杀/漏检 + κ
  → write_reports()
      → report.json + report.md
  → artifact-checksums.sha256 + receipt.json
```

生成媒体目录被本地 `.gitignore` 忽略，任何克隆都能一键重建；稳定、脱敏的聚合
Evidence 可提交。Receipt 不依赖“目录里大概有文件”，而是逐文件记录 bytes/hash。

## 4. 三个指标为什么这样算

### 4.1 人工观看时长节省率是主指标

```text
1 - Σ assisted_review_seconds / Σ baseline_full_watch_seconds
```

每个候选成对记录“没有工具时完整审核秒数”和“使用工具后的实际运营审核秒数”。
独立盲评是建立 ground truth 的评测成本，单列且不混入运营负担。统计器对候选成对
bootstrap；若 assisted 更慢，保留负值。`operational_full_watch` 只计算辅助的完整
观看规避率，不能替代主指标。

### 4.2 误杀必须包含所有仍可交付素材

分子是被机器 `AUTO_REJECT`、但人工裁决为 `EXCELLENT` **或** `ACCEPTABLE` 的
候选。只数优秀会漏掉“有轻微问题但本可交付”的错误淘汰。精确重复排除不是质量
淘汰；`ANALYSIS_ERROR` 是系统失败，两者都不能混入分母。

### 4.3 漏检只看真实交付后缺陷

分母是有交付后裁决记录的 delivered 候选，分子是命中预注册明显缺陷 taxonomy 的
候选。缺失不填 false；统计器保留 observed-only 比例和 missing count。

二元误杀/漏检/规避率使用 95% Wilson 区间。任一比例分母小于 30 都显示小样本
警告；区间只表达随机抽样不确定性，不能修复选择偏差或标签错误。

## 5. Schema 执行边界

项目没有新增第三方 Python 依赖。`jsonschema_subset.py` 真实执行当前两个 Schema
使用的 required、additionalProperties、enum/const、type、`$ref`、条件、数组、
pattern、上下界和 date-time；若 Schema 新增未支持 keyword，先 fail，而不是忽略。

它不是完整 Draft 2020-12 conformance 实现。未来真实 intake 应在受控环境再用成熟
validator 做第二次验证。当前单测专门证明 required 缺失、多余字段、非法枚举和未知
keyword 都会失败；运行时再加字节/hash/盲评隔离等 JSON Schema 无法表达的不变量。

## 6. 合成彩排究竟证明什么

**FACT**：本地生成器、Schema/invariant 校验、统计边界、双格式报告、provenance 与
checksum 链可以复现；异常容器 probe 失败、正常媒体 probe 成功；压力 manifest 是
300 条；这次 F11 合成彩排本身没有真实 Provider 调用，也没有常驻服务。F6 后续的
真实 Provider 合成产品链门禁是独立 Evidence，不能替代 F11 真实客户试点。

**INFERENCE**：拿到正确授权、真实数据、原始机器 Evidence 和锁定盲评后，这套工具
可以接收相同契约并生成描述性报告。

**UNKNOWN**：客户实际节省、误杀、漏检、模型质量/成本/延迟、生产吞吐与预注册阈值
能否满足。300 条压力记录只验证 manifest/parser，不是 300 条上传或性能测试。

```bash
./scripts/pilot/run-synthetic-rehearsal.sh
python3 -m unittest discover -s tests/pilot -v
python3 -m json.tool experiments/pilot/evidence/synthetic-rehearsal/receipt.json >/dev/null
python3 -m json.tool experiments/pilot/evidence/synthetic-rehearsal/report.json >/dev/null
git diff --check -- scripts/pilot experiments/pilot docs/pilot tests/pilot
```

机器结果从以下文件开始核对：

- `receipt.json`：最终 PASS/FAIL、policy、计数与逐文件 hash；
- `validation.json`：Schema 与 300+ 运行时不变量；
- `metrics.json`：完整分子/分母/秒数/区间/缺失/限制；
- `report.json`：机器报告；`report.md`：同源的人读报告；
- `artifact-checksums.sha256`：所有合成输入输出的 byte provenance。
