# F11 数据清单、Manifest 与合规边界

## 1. 两套数据永不混淆

| 分类 | 用途 | 可否进入 Git | Provider |
|---|---|---|---|
| `SYNTHETIC_REHEARSAL` | 验证 Schema、标注、指标、报告和压力清单 | 代码/Schema/脱敏 Evidence 可；可再生媒体默认忽略 | 仅 `DISABLED`/显式 Fake |
| `REAL_PILOT` | 验证真实客户价值 | 客户媒体、身份、原始标注、签名 URL 均不可 | 仅在所有者当次确认后 |

机器契约是 `experiments/pilot/schemas/pilot-manifest.schema.json`；标注字段契约是
`experiments/pilot/schemas/annotation-record.schema.json`。Schema 是格式约束，运行时
validator 还会检查路径逃逸、symlink、字节长度、SHA-256 和分类不变量。

仓库不新增第三方 Python 依赖，因此本地 validator 使用一个 fail-closed Draft 2020-12
子集执行器：它真实执行当前 Schema 出现的 `required`、`additionalProperties`、
`enum/const`、type、`$ref`、条件、数组、pattern 与 date-time 等关键字；Schema 一旦
加入未支持关键字会直接失败。它不是完整的官方一致性实现，真实生产 intake 还应在
受控环境用成熟 Draft 2020-12 validator 做第二次校验；单测专门覆盖上述三类易漏边界。

## 2. 必需数据清单

| 对象 | 必需字段/证据 | 原因 |
|---|---|---|
| Dataset | `datasetId`、classification、创建时间 | 隔离合成与真实证据 |
| 数据政策 | 是否客户/个人数据、权利基础、审批引用、删除日期 | 证明可处理且会按期删除 |
| Provider | mode、是否允许真实调用、脱敏调用 Evidence 引用 | 防止默认/隐式真实调用 |
| Brief | 相对路径、bytes、SHA-256 | 固化创作要求 |
| Profile | 相对路径、bytes、SHA-256 | 固化规则、模型逻辑 ID 与阈值 |
| Batch | batch ID、purpose、capacity、metric scope | 防止压力清单混入价值指标 |
| Candidate | blind-safe ID、媒体 hash/bytes、异常预期、重复关系 | 字节可复核且不靠文件名猜测 |
| 机器结果 | 状态、Finding、排名、选择、事件时间 | 指标分母与时长来源 |
| 人工结果 | baseline 全看秒数、assisted 运营秒数、完整观看动作、A/B 盲评、裁决、交付缺陷 | 三个产品指标来源；盲评秒数不混入运营负担 |
| Provenance | Git SHA、输入 hash、脚本 hash、工具版本 | 报告可复现 |

## 3. 文件引用规则

- manifest 内只能保存数据根相对路径，不允许绝对路径、`..` 逃逸或 symlink；
- 每个引用保存 `sizeBytes` 与小写 SHA-256；真实 intake 校验会重新读取 bytes；
- 真实媒体数据根必须在 Git 仓库外；校验 receipt 也留在同一受控根；
- 报告不记录客户姓名、邮箱、媒体路径、candidate ID、Provider endpoint、Key 名/值、
  access token、presigned URL；需要关联时使用审批系统中的不透明 reference；
- 一个逻辑模型 ID 不得原地换绑实际模型；调用 Evidence 需记录逻辑 ID 与实际模型名，
  但不记录端点或密钥。

## 4. 真实数据目录建议（仓库外）

```text
<authorized-pilot-root>/
├── manifest.json
├── brief/brief.md
├── profile/profile.json
├── media/                       # 权限最严，按期删除
├── machine-evidence/            # 状态、Finding、排名、事件、脱敏调用证据
├── annotations/
│   ├── reviewer-a.csv
│   ├── reviewer-b.csv
│   ├── adjudicated.csv
│   └── batch-runtimes.json
└── evidence/                    # intake/metrics/report/receipt，仍属受控数据
```

不要把真实数据根指向 `/tmp`、仓库、同步网盘公共目录或个人桌面散落目录。

## 5. 生命周期

1. intake 前记录权利人、用途、最小范围、访问人和删除日期；
2. 原始媒体只授予运行与盲评所需人员最小权限；
3. 处理过程中记录访问/导出/异常，不把密钥写入 Evidence；
4. 客户撤回或到期时停止处理，删除媒体、派生帧和盲评缓存；
5. 生成删除 receipt：dataset ID、删除时间、责任人、对象数量、失败项；
6. 只保留审批允许的脱敏聚合数据。若聚合样本可反推出客户，也按受控数据处理。

## 6. 合成数据说明

一键彩排生成 10 条具名媒体夹具、4 张关键帧、10 条指标标注和 300 条压力 manifest
记录。压力记录复用已生成的合成 bytes，只验证最大容量清单与解析路径；没有上传到
应用，不能宣称吞吐、并发、数据库或队列容量已验证。
