# F11 真实试点方案（待所有者授权执行）

> 当前状态：工程方案已准备，真实批次未执行。本文不是试点结果。
> 真实 Provider、真实客户媒体和线上操作仍是外部门禁；开始前必须取得所有者
> 当次明确确认，并完成数据权利与留存审批。

## 1. 为什么做

FrameFlow Select 的价值底线不是“跑通接口”，而是在尽量不误伤优秀视频的前提下，
减少运营人员完整观看候选的数量。真实试点必须回答三个问题：

1. 人工完整观看量是否实质下降；
2. 确定性自动淘汰是否误伤优秀视频；
3. 最终交付是否仍漏掉明显缺陷。

合成彩排、Fake Provider、离线单测和本地压力清单都不能回答这些问题。

## 2. 试点对象与最小范围

推荐选择一个有稳定批量生成流程、愿意提供审核时间记录的真实 AI 视频团队：

- 至少 3 个不同 Brief 的独立批次，避免一个题材替代全部业务；
- 每批 20–300 条，遵守产品容量边界；
- 每批固定一个不可变 Brief 与一个 Quality Profile 版本；
- 真实模型由平台白名单选择并固化 `modelId`，调用前另行取得所有者确认；
- 至少 2 名互不沟通的盲评员，另设 1 名裁决员；运营审核与盲评尽量由不同人承担。

docs/03 的最低完成定义只要求一个真实批次完整走完；但单批次通常只能说明“流程
可执行”，不能稳定外推客户价值。推荐 3 批及以上，并以每个指标的实际分母判断
证据是否充足，而不是只看总候选数。

## 3. 角色与职责

| 角色 | 职责 | 不能做 |
|---|---|---|
| 所有者 | 批准真实 Provider/数据范围、预注册阈值、最终价值判断 | 事后为迎合结果改阈值 |
| 数据权利人 | 证明媒体处理权、确认留存/删除日期 | 把未授权第三方媒体混入批次 |
| Operator | 按真实工作方式运行批次并记录观看动作/时长 | 为改善指标跳过本应观看的候选 |
| Reviewer A/B | 在看不到机器结论的情况下独立标注 | 讨论标签或查看另一人的答案 |
| Adjudicator | 在双人提交锁定后裁决分歧 | 回写或覆盖两份原始盲评记录 |
| Evidence custodian | 固化 SHA-256、版本、时间线与事件记录 | 把密钥、签名 URL 或客户身份写进报告 |

## 4. 开始前门禁（缺一项即停止）

1. 所有者当次书面确认：允许处理精确列出的批次，并允许精确指定的真实模型调用；
2. 数据权利/用途/保留期限/删除方式已写入 manifest，审批引用可查；
3. 客户媒体存放在 Git 仓库外的受控目录；仓库内只保留 Schema 与脱敏聚合报告；
4. Brief、Profile、模型逻辑 ID、检测器版本、聚类阈值、统计口径和成功阈值已冻结；
5. 盲评包只含随机盲评 ID 与媒体访问方式，不含 candidate ID、文件名语义、机器状态、
   Finding、排名或预期异常；
6. 回滚/停止联系人、数据泄露停止条件、Provider 预算上限和删除日期已确认；
7. 真实部署、备份恢复与生产权限由所有者亲手完成，本方案不替代 F9/F10 门禁。

## 5. 预注册指标口径

| 指标 | 分子 / 分母 | 关键边界 |
|---|---|---|
| 人工观看时长节省率（主） | `1 - Σ assisted_review_seconds / Σ baseline_full_watch_seconds` | 候选成对记录；独立盲评用时单列，不计运营负担；用 paired bootstrap 区间 |
| 完整观看规避率（辅助） | 未发生运营完整观看的候选 / 运营观看状态已记录的候选 | 只解释工作流覆盖，不能替代时长节省 |
| 误杀率 | 经裁决为 `EXCELLENT` **或** `ACCEPTABLE` 的自动淘汰候选 / 已纳入盲审且有裁决标签的 `AUTO_REJECT` 候选 | 两类都可交付；重复排除不是质量淘汰；系统错误绝不进入分母 |
| 漏检率 | 裁决为有明显缺陷的交付候选 / 有交付后裁决记录的交付候选 | 只依据预注册缺陷 taxonomy；缺失不填 0 |
| 批次处理时长 | `rankingReadyAt - uploadCompletedAt` | 失败/重试保留原始事件，不能只记录最快一次 |
| 盲评一致性 | raw agreement + Cohen's κ | κ 无标签方差时为 N/A；不伪造 1.0 |

二元比例输出 95% Wilson 区间；时长节省率对候选的 baseline/assisted 秒数做固定 seed
成对 bootstrap。分母为 0 时值与区间为 `null`；样本小于 30 时强制显示小样本警告；
缺失值不插补，只报告 observed-only 值与缺失数。assisted 比 baseline 更慢时保留负值。

## 6. 推荐的预注册成功阈值

以下是面向产品底线的推荐值，必须在查看真实结果前由所有者和试点方确认或修改：

- 人工观看节省率点估计 ≥ 30%；
- 误杀率点估计 ≤ 2%，且 95% 区间上界 ≤ 5%；
- 漏检率点估计 ≤ 5%，且 95% 区间上界 ≤ 10%；
- 不允许把 `ANALYSIS_ERROR` 计作视频淘汰；发生即作为系统可靠性问题单列；
- Cohen's κ 建议 ≥ 0.60；低于该值先复查协议与 taxonomy，不能直接归因产品；
- 批次处理时长在试点前填写业务可接受 SLA，本方案不凭空发明统一秒数。

稀有错误指标的关键是分母。若误杀为 0，简单“rule of three”近似要求约 60 个
独立被审自动淘汰样本，才能把 95% 上界压到约 5%；Wilson 口径的精确结果以脚本
为准。达不到分母时结果标为 `INCONCLUSIVE`，而不是把 0 次错误写成 0 风险。

## 7. 执行顺序

1. **冻结方案**：保存 manifest、Brief、Profile、模型目录条目、阈值和本文件版本哈希；
2. **安全入场**：在仓库外创建受控数据根，执行只读 intake 校验；
3. **运行批次**：真实上传→分析→聚类排名→Operator 复核→锁定 SelectionSet；
4. **固化机器层**：导出状态、Finding、排名、选择、事件时间线和 Provider 脱敏证据；
5. **生成盲评包**：固定 seed 随机化 blind ID；Reviewer A/B 独立提交并锁定哈希；
6. **裁决**：只对分歧项裁决，保留 A/B 原始标签与裁决人/时间/理由；
7. **统计**：运行 `calculate_metrics.py`，不得手改 JSON；
8. **报告**：同时生成机器 JSON 和 Markdown；按 FACT / INFERENCE / UNKNOWN 汇报；
9. **所有者审批**：所有者依据预注册阈值选择 `SUPPORTED / NOT_SUPPORTED / INCONCLUSIVE`；
10. **删除/归档**：到期删除媒体并留删除 receipt；脱敏指标按审批策略保留。

## 8. 停止条件

出现任一项立即停止新增处理：授权范围不清、盲评泄露机器答案、真实调用未获当次
确认、预算异常、媒体权利争议、客户撤回、密钥/签名 URL 出现在日志、Profile 或
模型路由漂移、Evidence 哈希不一致。已产生的事实只做事件记录，不能静默重跑覆盖。
