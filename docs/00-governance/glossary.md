# 术语表

| 术语 | 定义 |
|---|---|
| 团队 | FrameFlow 内协作与资源归属边界 |
| 项目 | 为客户或内部内容创建的生产单元 |
| Brief | 项目需求说明；可有多个版本，仅一个当前版本 |
| 任务 | 被分配给成员的制作工作项 |
| 素材 | 逻辑媒体资产 |
| 素材版本 | 素材不可变的具体文件/内容版本 |
| Suggestion | AI 生成但尚未人工确认的建议 |
| 审核 | 对素材/版本/交付的通过、驳回或返工流程 |
| 交付包 | 固定引用具体版本的可追溯交付集合 |
| 模块化单体 | 一个部署单元内按领域模块组织、通过规则限制依赖的应用 |
| 模块边界 | 模块可以拥有、调用和暴露的职责与接口边界 |
| 限界上下文 | 对一个领域模型和语言负责的边界 |
| 服务边界 | 一个可独立部署、扩缩容和治理的运行单元边界 |
| 数据所有权 | 某服务唯一负责写入和迁移某组业务数据的责任 |
| 防腐层 | 阻止外部模型、服务或技术细节污染本领域模型的适配层 |
| Port/Adapter | 通过抽象端口隔离领域与数据库、对象存储、AI 或消息实现 |
| 领域事件 | 已经发生的业务事实，例如 `delivery.confirmed` |
| 命令消息 | 请求某个消费者执行动作的消息，例如素材分析任务 |
| Outbox | 与业务事务同写的事件记录，用于可靠异步发布 |
| Idempotency | 同一个业务请求或事件重复到达时只产生一次有效结果 |
| Saga/补偿 | 多服务操作失败时通过反向动作或待处理状态恢复一致性 |
| Gateway | 对外统一入口，负责路由、入口鉴权、限流和错误映射 |
| 服务发现 | 查找可用服务实例的机制；Compose 与 Kubernetes 的实现不同 |
| ConfigMap | Kubernetes 中保存非敏感配置的资源 |
| Secret | Kubernetes 或运行环境中保存敏感配置的注入载体 |
| readiness | 表示实例是否可以接收业务流量 |
| liveness | 表示实例是否仍然存活，失败可能触发重启 |
| startupProbe | 启动较慢应用在初始化期间使用的探针 |
| HPA | Kubernetes Horizontal Pod Autoscaler，按指标调整副本数 |
| PDB | PodDisruptionBudget，限制主动维护时的可用性损失 |
| sidecar | 与业务容器共同运行、承担代理或辅助能力的容器 |
| VirtualService | Istio 中定义请求路由和流量分配的资源 |
| DestinationRule | Istio 中定义服务版本、连接池和流量策略的资源 |
| mTLS | 双向 TLS，用于服务间身份认证和加密通信 |
| AuthorizationPolicy | Istio 中控制工作负载访问权限的策略 |
| 灰度发布 | 先向小比例流量发布新版本并观察，再逐步扩大 |
| FACT | 已通过代码、命令或证据验证的事实 |
| DECISION | 已批准、指导实现的决策 |
| PLAN | 尚未实现的阶段计划 |
| PROPOSAL | 待批准的方案 |
| UNKNOWN | 尚未决定或没有证据的事项 |
| EVIDENCE | 可复现的命令、原始输出、报告或故障记录 |
