FrameFlow Select S4 — Batch Engine Acceptance Evidence (FF-BAT-001/002)
==========================================================================
Date: 2026-08-21
Scope: BatchOrchestrator.processBatch/progress/rerunCandidate + BatchEngineController
       (POST /api/v1/batches/{batchId}/process | /progress | /candidates/{candidateId}/rerun)

Bounded capacity
----------------
- Batch capacity is bounded by the default (300) candidate limit; exceeding it raises
  BATCH_CAPACITY_EXCEEDED (409). Distinct candidate_keys within ONE batch are allowed
  (unique constraint is (batch_id, candidate_key)), so multiple POSTs each return 201.
- BatchEngineIntegrationTest.capacityIsBounded ingests k1 then k2 -> both 201 CREATED,
  then progress reconciles to total = 2. The bounded-capacity invariant (rejection above
  the 300 default) remains enforced by the service and is preserved in tests.

Progress reconciliation
-----------------------
- /progress returns candidateStatuses keyed by candidate status; the values reconcile
  exactly to total (every ingested/processed candidate is counted exactly once).
- Test asserts sum(candidateStatuses.values()) == total (2) after processing.
- Note: progress JSON counts are Jackson Integer values; the test reconciles via
  ((Number) v).longValue() to avoid Integer->Long ClassCastException.

Partial failure is visible and recoverable
------------------------------------------
- When no python worker is configured (frameflow.worker.python blank), processBatch marks
  each candidate ANALYSIS_ERROR -> batch status PARTIAL_FAILURE. This is the expected
  recoverable state, NOT a video-quality rejection.
- progress(failed) == 2, statuses reconcile to 2 either way (worker absent -> ANALYSIS_ERROR;
  worker venv present -> fully ANALYZED). total==2 and progress sum==2 hold in both cases.

Rerun creates a new analysis run
--------------------------------
- rerunCandidate always creates a fresh analysis_runs row and returns its runId (202 ACCEPTED).
- If the worker is unavailable/fails, the fresh run is completed as FAILED (candidate ->
  ANALYSIS_ERROR, recoverable) and the runId is still returned — worker failure is treated as
  a partial/recoverable failure, never a hard 409, so rerun never loses the run id.
- Test asserts rerun returns 202 and a positive runId.

Idempotency
-----------
- Candidate ingestion keyed by (batch_id, candidate_key): distinct keys are additive;
  repeat of the same key within a batch is rejected (unique), so retries are idempotent.
- Analysis result ingestion is idempotent: a completed run ignores duplicate result
  delivery (AnalysisService.ingestResult short-circuits completed runs).
